# Deploying

Two services: the Express API and Postgres on **Render**, the React SPA on
**Vercel**. They find each other through environment variables, so the order
below matters — the API needs the Vercel origin for CORS, and the SPA needs the
Render URL to call.

Both platforms deploy from Git, so the repo needs a remote first.

---

## 0. Push the repo

```bash
git remote add origin git@github.com:<you>/returns-manager.git
git push -u origin main
```

`.env` is gitignored and must stay that way. Every secret below is entered in a
dashboard, never committed.

---

## 1. Generate the secrets you'll need

Run these locally and keep the output somewhere safe — a password manager, not
a text file:

```bash
openssl rand -hex 32
```

That's your **`ENCRYPTION_KEY`**. It encrypts Shopify access tokens at rest.
Generate it once and never change it: once a store is connected, a different
key makes every stored token undecryptable and the only fix is reinstalling the
app on every shop.

`JWT_SECRET` is generated by Render automatically — you don't need to make one.

---

## 2. Render: API + database

**New → Blueprint**, point it at the repo. It reads `render.yaml` and creates
both the Postgres instance and the web service.

Render will prompt for the values marked `sync: false`. Fill in what you can
now and come back for the rest:

| Variable | Value |
| --- | --- |
| `ENCRYPTION_KEY` | the 64-hex string from step 1 |
| `SHOPIFY_API_KEY` | from the Shopify Partner Dashboard |
| `SHOPIFY_API_SECRET` | from the Partner Dashboard — see the rotation note below |
| `APP_URL` | *leave blank for now* — you get it after the first deploy |
| `CORS_ORIGINS` | *leave blank for now* — you get it from Vercel |
| `PORTAL_BASE_URL` | *leave blank for now* |
| `SMTP_*`, `MAIL_FROM` | your Resend credentials |

Once it deploys you'll have a URL like `https://returns-manager-api.onrender.com`.
Set **`APP_URL`** to exactly that and redeploy.

> **Rotate the Shopify secret first.** The current one was pasted into a chat
> during development. Regenerate it in the Partner Dashboard and use the new
> value here and in your local `.env`.

> **Free plan caveats.** Free Postgres is deleted after 30 days. Free web
> services sleep after inactivity, so the first request after a quiet period
> takes ~50s — long enough that a Shopify webhook can time out and retry.
> Move both to paid before this handles real returns.

> **`preDeployCommand` needs a paid instance.** On the free plan, delete that
> line from `render.yaml` and append `&& npm run db:deploy --workspace server`
> to `buildCommand` instead.

---

## 3. Vercel: the SPA

**Add New → Project**, import the same repo and set **Root Directory** to
`client`. `client/vercel.json` supplies the build command, output directory and
the SPA rewrite — don't override them in the UI.

Paths in that file are relative to the Root Directory, which is why it lives
beside the client rather than at the repo root.

Add one environment variable, for **all** environments:

```
VITE_API_URL = https://returns-manager-api.onrender.com
```

This is read at *build* time, not runtime — Vite inlines it into the bundle. If
you change it later you must redeploy, not just restart.

Deploy. You'll get something like `https://returns-manager.vercel.app`.

---

## 4. Point the two at each other

Back in Render, set both to your Vercel URL and redeploy:

```
CORS_ORIGINS    = https://returns-manager.vercel.app
PORTAL_BASE_URL = https://returns-manager.vercel.app
```

`CORS_ORIGINS` accepts a comma-separated list. Vercel gives every branch its own
preview URL, and those are *not* covered by the production one — add them
explicitly if you want previews to talk to the live API.

Check it's alive:

```bash
curl https://returns-manager-api.onrender.com/api/health
```

---

## 5. Repoint Shopify

`shopify.app.toml` holds the origin Shopify redirects to and posts webhooks at.
Both URLs must share a host, or OAuth fails with "redirect_uri and application
url must have matching hosts":

```toml
application_url = "https://<your-service>.onrender.com"

[auth]
redirect_urls = [
  "https://<your-service>.onrender.com/api/shopify/callback"
]
```

Then `shopify app deploy` to push the config, and reinstall the app on your
store. Reinstalling re-registers the webhooks against the new URL — without it
Shopify keeps posting wherever it was pointed before, usually a dev tunnel
that no longer exists.

Set `APP_URL` on Render to the same origin. The app signs its own OAuth state
and builds callback URLs from it, so a mismatch here fails the install even
when the Partner Dashboard is correct.

---

## 6. Create your admin account

**This is the step that's easy to miss.** Installing the app creates the
merchant, its policy, reason groups and branding — but no staff account,
because Shopify never gives us a password. Until you run this, `/admin/login`
has nothing to accept.

From Render's **Shell** tab on the API service:

```bash
ADMIN_EMAIL=you@yourstore.com ADMIN_PASSWORD='choose-a-long-one' npm run create-admin --workspace server
```

Pick the password yourself; nothing is defaulted and it must be at least 12
characters. Re-running with the same email resets that password, which is also
how you recover a lost one.

Do **not** run `db:seed` in production — that's the local demo store, complete
with a publicly known password.

---

## What to check once it's up

1. `/api/health` returns `{"status":"ok"}`
2. Admin login works at `https://<vercel-url>/admin/login`
3. Settings shows your store as connected
4. A test order appears after a webhook fires — place one in Shopify and watch
   Render's logs
5. The portal finds that order at `https://<vercel-url>/r/<your-slug>`

---

## Known gaps before real customers

These are unfinished rather than broken, and each has come up during
development:

- **GDPR webhooks.** Shopify requires `customers/data_request`,
  `customers/redact` and `shop/redact` for any public app. Not implemented.
- **Email deliverability.** Verify a sending domain in Resend. Unverified
  senders land in spam or are rejected outright.
- **`read_all_orders`.** Without it Shopify hides orders older than 60 days, so
  the portal can't find them. Requesting it needs Shopify's approval.
- **Return labels.** No carrier integration — approved returns tell the shopper
  a label is coming, and nothing sends one.
- **No tests.** Nothing guards a regression on refund maths.
